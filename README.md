ТЗ-5. Разработка собственного компонента

Страница расположена: https://cb313664.tw1.ru/currency_component.php

Описание компонента
- калькулятор: выберите валюту и введите сумму. Система автоматически пересчитает её в российские рубли по актуальному курсу,
- фильтр: используйте панель над таблицей, чтобы найти нужную валюту по коду, названию или статусу базовой валюты,
- таблица: показывает список валют. На странице отображается по 2 записи, переключаться между страницами можно с помощью кнопок внизу таблицы,
- курс: все значения в таблице и калькуляторе указаны по отношению к российскому рублю (RUB).

Описание по реализации
- структура компонента: папка /local/components/table_component/ содержит файлы class.php (логика), .description.php (название в редакторе), .parameters.php (настройки) и папку templates/.default/template.php (шаблон),
- классы: используется Bitrix\Currency\CurrencyTable для получения валют из базы и Bitrix\Currency\CurrencyLangTable для локализованных названий,
- калькулятор, обновляется только цифра: реализован через интерфейс Controllerable и метод calcAction. Обновляется через BX.ajax.runComponentAction, чтоб не обновлять стрницу при каждом нажтии на кнопку "Рассчитать",
- фильтр и таблица: компоненты bitrix:main.ui.filter и bitrix:main.ui.grid связаны через одинаковый идентификатор currency_list_grid,
- параметры: для фильтра — FILTER_ID, GRID_ID, FILTER; для таблицы — GRID_ID, COLUMNS, ROWS; для навигации — NAV_OBJECT,
- постраничная навигация: реализована через Bitrix\Main\UI\PageNavigation с размером страницы 2, передаётся в таблицу как NAV_OBJECT.

Описание реализации компонента и модуля

- переход к модулю сделан по кнопке "Заказать запчасти", 
- компонент создан для работы с услугами автосервиса в одном интерфейсе,
- пользователю не нужно переключаться между административной панелью и публичной частью сайта для управления услугами,
- все действия (добавление, редактирование, удаление, привязка запчастей) выполняются прямо на странице,
- class.php — класс компонента UslugiServisaComponent, реализует интерфейс Controllerable для обработки AJAX-запросов. Содержит методы получения услуг, запчастей и остатков, а также экшены для сохранения, удаления и получения данных формы,
- template.php — шаблон компонента, содержит верстку (таблица, модальное окно, вкладки), CSS-стили и JavaScript, AJAX,
- если нажать на кнопку «Добавить услугу». Открывается модальное окно с пустыми полями,
- после заполнения полей и нажатия «Сохранить» JavaScript собирает все и отправляет AJAX-запрос через BX.ajax.runComponentAction с указанием signedParameters,
- на сервере срабатывает метод saveRowAction. Он проверяет наличие ID: если ID = 0, создается новый элемент через CIBlockElement::Add. Если ID > 0, элемент обновляется через CIBlockElement::Update,
- после успешного сохранения таблица перезагружается через reloadTable, и пользователь видит обновленные данные,
- чтоб редактировать услугу, нужно выбрать «Редактировать» в меню строки, отправляется AJAX-запрос к методу getFormDataAction с ID услуги,
- возвращаюся данные услуги (название, цену, нормо-часы, привязанные запчасти),
- JavaScript заполняет этими данными модальное окно и открывает его, при сохранении используется тот же saveRowAction,
- чтоб удалить услугу, отправляется AJAX-запрос к методу deleteRowAction с ID услуги, сервер удаляет элемент через CIBlockElement::Delete,
- таблица перезагружается без перезагрузки страницы,
- услуги хранятся в инфоблоке с ID 25, запчасти — в инфоблоке 14. ID инфоблоков передаются жестко в JavaScript и в class.php (в методах getAllParts и getPartsNames),
- для получения цен и остатков запчастей используется модуль catalog. Сначала проверяется наличие торговых предложений через CCatalogSKU::getOffersList. Если они есть, берется цена и остаток из первого предложения через CPrice::GetList и CCatalogProduct::GetList. Если предложений нет — данные берутся из самого товара,
- ссылки на карточки запчастей в CRM формируются динамически по шаблону /crm/catalog/{ID_ИНФОБЛОКА}/product/{ID_ТОВАРА}/ и подставляются в таблицу,
- в классе реализован интерфейс Controllerable и метод configureActions, который возвращает пустые prefilters для экшенов saveRow, deleteRow и getFormData. Это отключает стандартную проверку CSRF-токена, которая мешала при AJAX-вызовах,
- мнтерфейс меняется в зависимости от выбранного режима с помощью JavaScript,
- в режиме «По закончившимся»: поле «Количество для заявки (по умолчанию)» отображается, в таблице товаров колонка «Кол-во для заявки» скрывается. Это нужно, чтобы пользователь не пытался вручную задать количество для товаров, которые модуль находит автоматически (у которых остаток ≤ 0),
- в режиме «По выбранным»: поле «Количество по умолчанию» скрывается, В таблице товаров колонка «Кол-во для заявки» становится доступной. Это позволяет указать точное количество только для тех товаров, которые пользователь хочет заказать,
- модуль работает с инфоблоком товаров (ID 14) и использует модуль catalog, для получения остатков используется последовательность,
- сначала модуль проверяет, есть ли у товара торговые предложения (SKU) через CCatalogSKU::getOffersList().
- если предложения есть, берется первое предложение и его остаток через CCatalogProduct::GetList().
- Если предложений нет, берется остаток самого товара.
- остаток выводится в таблице рядом с названием товара. Если остаток ≤ 0 — он подсвечивается красным,
- как пользоваться списком запчастей в каждом режиме,
- в режиме «По закончившимся»: список запчастей служит только для справки (визуального контроля). Пользователь не взаимодействует с ним. Модуль сам проходит по всему инфоблоку, находит товары с остатком ≤ 0 и создает для них заявки с количеством из поля «По умолчанию»,
- в режиме «По выбранным»: пользователь вручную вписывает нужное количество в колонку «Кол-во для заявки» напротив тех товаров, которые нужно заказать. Модуль берет только те строки, где количество > 0, и создает для них заявки,
 - .description.php — файл содержит массив $arClass с ключами ID, NAME, DESCRIPTION. Он используется для отображения названия и описания модуля в списке установленных решений, сделан для определения модуля в административной панели,
- include.php — файл содержит подключение автозагрузки классов модуля (через Loader::registerAutoLoadClasses), сделан для того, чтобы при обращении к классам модуля (например, DraftTable) они подгружались без подключения файлов,
- lib/DraftTable.php — класс, описывающий ORM-сущность для работы с таблицей custom_autoorder_drafts. Сделан для того, чтобы можно было удобно работать с записями истории заявок через методы add, getList и т.д.
- install/index.php — класс custom_autoorder, наследующий CModule,
- метод DoInstall() регистрирует модуль через RegisterModule(), создает таблицу в базе данных через SQL-запрос CREATE TABLE (в методе InstallDB()) и регистрирует пункт меню в админке через RegisterModuleDependences() (обработчик OnBuildGlobalMenu),
- метод DoUninstall() удаляет таблицу из базы данных через DROP TABLE (в методе UnInstallDB()) и снимает регистрацию модуля через UnRegisterModule(),
- метод OnBuildGlobalMenu() добавляет ссылку на страницу настроек модуля в левое меню административной панели,
- оptions.php — файл страницы настроек и логики создания заявок,
- подключает модули iblock, catalog и crm через Loader::includeModule(),
- обрабатывает POST-запрос сохранения настроек: получает выбранную воронку, режим, количество по умолчанию и индивидуальные количества, сохраняет их через Option::set(),
- обрабатывает POST-запрос создания заявок: в зависимости от выбранного режима либо ищет все товары с остатком ≤ 0, либо берет только товары с указанным количеством. Для каждого товара вызывается функция createAutoorderDeal(),
- функция createAutoorderDeal() создает сделку через CCrmDeal и привязывает к ней товар через ProductRowTable::add(),
- выводит HTML-форму с вкладками «Настройки» и «Инструкция», таблицей товаров и кнопками. Использует JavaScript для скрытия/показа полей в зависимости от выбранного режима,
- выводит список успешно созданных сделок в виде HTML-списка со ссылками на карточки в CRM (формат /crm/deal/details/{ID}/),
- для получения остатков используется модуль catalog, сначала проверяется наличие торговых предложений (SKU) через CCatalogSKU::getOffersList(), затем берется остаток из CCatalogProduct::GetList(), если предложений нет — остаток берется у самого товара.
